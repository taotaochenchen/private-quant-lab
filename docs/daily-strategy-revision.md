# 每日建议与人工执行

## 当前方向

暂停桌面自动化与实盘执行推进。首页使用 `pre_market` 建议工作流，不再启动自动模拟订单。原有模拟盘 API 仍保留供独立测试，并未删除；建议工作流通过工具白名单隔离下单能力。

T-1 指上一交易日，不是自然日昨天，也不是把所有品种统一解释成某个结算规则。已接入 `domain.TradingCalendar`：当 akshare 交易日历可用且覆盖查询日期（`verified=true`）时，自动推算 T-1 并交叉校验用户给出的日期；否则回退到 `weekday_only`（仅排除周末，不含交易所节假日），仍需人工确认。输出始终如实标记 `calendar_verified` 与 `calendar_source`，不能把工作日减一当作已接入交易日历。

## 决策输入

1. 上一交易日报告：保留昨日方向、候选标的、条件、失效条件与证据，作为研究基线。
2. 人工执行反馈：是否执行、是否部分执行以及账户变化，由用户自述，不代表券商已核验。未填写则执行与持仓状态未知，不假设昨日买入。
3. 今日证据：市场、新闻、行业、算子与风控仍重新运行，使用同一次 run 的统一截止时间；昨日结论不能替代今日数据。

所有 Agent 的输入均含 `decision_context` 与上游节点结论；即使编辑 SP，人工执行边界仍附加到 SP，执行层只暴露研究工具。当前上游市场工具仍以 mock 为主，不能将流程结果当作真实交易依据。

## 今日输出

原 PreMarketReport 增加服务端计算的 `strategy_revision`：

- `retained`：建议结构未变。
- `adjusted`：仓位、方向或条件等字段变化，附 changed_fields 和前后原值。
- `withdrawn`：今日报告不再包含昨日建议，不等于要求卖出。
- `suspended`：今日被阻断/待审核而没有建议，不等于逻辑反转或已平仓。
- `added`：历史基线中没有的今日建议。
- `initial`：没有 T-1 基线时的首次建议，不声称完成跨日复盘。

同时展示前后市场状态、今日报告说明和证据引用。变化分类为确定性结构对比，逐标的因果解释尚未独立校验，不能把字段变化自动归因为某条新闻。模型负责在今日说明中解释调整理由，不允许模型修改历史原值。

## 使用与限制

首页可选择上一交易日 PreMarketReport JSON，人工确认其交易日（或在校验日历可用时由服务端自动推算），补充执行反馈，然后启动工作流。今日报告可下载作为下一次基线。无需券商持仓 XLS 才能运行研究流程。

遵循暂缓存储的要求，不写数据库、JSONL 或浏览器持久化；基线仅存在当前页面和当次请求中。刷新后需重新选择报告，跨日自动取上一份报告尚未实现。要免去这一步，需要后续单独允许保存最小决策快照，不必同时保存模型原始日志。

不会推算实际成交、收益、可卖量或真实持仓；依赖账户的建议必须人工核验。页面尚无按笔反馈表和账户对账，仅有可选文本反馈。模型日期不符时阻断建议，保留错误以便检查。当前为盘前调整，尚非实时盘中监控。
